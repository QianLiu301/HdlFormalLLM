01
BDD-Hardware Benchmark & Multi-LLM Evaluation
Months 1–3
HIGH PRIORITY

Key Tasks

  • Curate 50–100 hardware modules (ALU, FSM, FIFO, bus protocol, pipeline, etc.)
  • Create reference BDD scenarios + testbenches + golden DUTs for each module
  • Implement experiment logging (prompt, output, tokens, latency, model version)
  • Run controlled multi-LLM comparison (9 providers, 5+ repetitions, fixed params)
  • Build mutation testing framework (systematic bug injection into DUTs)

Evaluation Metrics

  • Scenario Completeness — coverage of spec functional points
  • Conversion Rate — BDD → Testbench success ratio
  • Simulation Pass@k — correctness on golden DUTs
  • Mutation Score — bug detection on fault-injected DUTs
  • Coverage % — statement/branch coverage achieved
  • Statistical significance — Wilcoxon / Mann-Whitney U tests
↓
02
Closed-Loop Simulation Feedback
Months 3–5
MEDIUM

Key Tasks

  • Feed simulation coverage reports back to LLM after initial generation
  • LLM generates supplementary BDD scenarios targeting coverage gaps
  • Implement iterative refinement loop (max N iterations)
  • Compare BDD-mediated feedback vs. direct testbench regeneration

Research Questions

  • How many iterations are needed to reach coverage saturation?
  • Does BDD as intermediate representation improve feedback efficiency?
  • Which LLMs respond best to coverage-gap feedback?
  • Coverage improvement curve: diminishing returns analysis
↓
03
Multi-Agent BDD Verification Pipeline
Months 5–8
EXPLORATORY

Agent Architecture

  • Spec Agent — extract functional points from NL specs
  • BDD Agent — generate behavioral scenarios
  • Testbench Agent — synthesize Verilog testbenches
  • Simulation Agent — execute & analyze results
  • Reviewer Agent — identify gaps, drive iteration

Expected Contributions

  • Quantify collaboration benefits vs. single-LLM baseline
  • Evaluate role specialization (same model vs. different models per role)
  • Measure end-to-end verification quality improvement
  • Compare with VeriMind & RTLSquad architectures

Expected Novel Contributions

Contribution 1
First BDD-Hardware Benchmark Suite with multi-LLM evaluation — filling a gap in existing benchmarks (CVDP, FVEval, VerilogEval)
Contribution 2
BDD-specific quality metrics for hardware verification (Scenario Completeness, Conversion Rate, Mutation Score)
Contribution 3
Systematic comparison of 9 LLM providers on BDD-driven hardware test generation — the most comprehensive multi-LLM study in this domain
Contribution 4
Evidence that BDD as intermediate representation improves iterative test refinement compared to direct testbench generation

Positioning vs. Related Work

Related Work Focus Our Differentiation
LLM-based BDD for HW (Bremen/DFKI, 2025) BDD scenario derivation from specs We add Multi-LLM comparison, benchmark, mutation testing, closed-loop feedback
AutoBench (TUM, 2024) Direct testbench generation We add BDD intermediate representation for better interpretability & iterability
LLM4Cov (VTS 2026) Coverage-driven agentic testbench We add BDD-mediated feedback loop; human-readable intermediate layer
CVDP / FVEval (NVIDIA / Berkeley) Benchmark for RTL generation & FV Gap filled No existing benchmark covers BDD-to-testbench pipeline
VeriMind (2025) Multi-agent Verilog generation We add BDD-specialized agent roles for verification (not generation)
